1. Simplify Add Patent

The current project workspace asks the user to manually enter:

Patent number
Patent title

Change this.

The user should ordinarily need to enter only the U.S. patent number.

The system should retrieve the patent's public bibliographic information and claims automatically.

Provide:

+ Add Patent

and support:

one patent number; or
multiple patent numbers pasted/entered together.

Accept common formats such as:

US 12,345,678 B2
12,345,678
12345678
US12345678B2

Normalize these into a consistent internal representation.

2. Retrieve authoritative/public patent information

Research and use an appropriate reliable patent-data source/API for U.S. issued patents.

Prefer an official USPTO source/API where practical.

Do not scrape Google Patents if an appropriate structured patent-data source is available.

For each patent retrieve, where available:

patent number
title
application number
filing date
issue date
earliest priority date
inventors
current/original assignee information as available from the selected source
abstract
claims
patent status/data-source status
source/provenance
date retrieved

Do not silently invent unavailable metadata.

3. Claims

Automatically retrieve the patent's claims.

Identify which claims are:

Independent
Dependent

Present the independent claims prominently.

Do NOT simply assume Claim 1 is the appropriate monitoring claim.

For example:

Independent Claims

☑ Claim 1 — Apparatus
☐ Claim 12 — Method
☐ Claim 20 — System

The user should be able to select one or multiple independent claims for monitoring.

Preserve the full original claim text exactly as retrieved from the source.

4. Human verification

Show:

Patent number
Title
Assignee

Provide an ADMIN/ATTORNEY manual correction mechanism where appropriate.

5. Duplicate handling

Do not permit the same patent to be accidentally added twice to the same project.

If it already exists, tell the user:

This patent is already being monitored in this project.

The same patent MAY exist in different client projects because projects are tenant-isolated.

7. Claim storage

Store claims as versioned records.

Preserve:

original retrieved claim text;
claim number;
independent/dependent status;
dependency where determinable;
retrieval source;
retrieval date;
human verification status; and
monitoring selection.

Do not overwrite attorney-reviewed claim text silently during a future refresh.

8. Security and tenant isolation

Continue using the UUID/public-ID architecture just implemented.

Patent routes and APIs must use non-enumerable public IDs.

Every patent request must independently verify access to the underlying project/client.

Knowing another client's patent UUID must not provide access.

Patent bibliographic information may itself be public, but the fact that a particular client is monitoring a particular patent is confidential client/project information and must remain tenant-isolated.

9. Data provenance

Maintain provenance for automatically retrieved information.

At minimum record:

source
retrieval timestamp
source identifier/URL where appropriate
whether information was automatically retrieved or manually modified
