Before we proceed further with the Patent Infringement Monitor, I want to change how projects and other client resources are publicly identified.

The current project URL exposes the sequential database ID:

/portal/projects/1

I do not want sequential internal database IDs exposed in portal URLs or client-facing APIs.

Please implement non-enumerable public identifiers for client-confidential resources.

Project IDs

Keep the existing internal numeric primary key if it is useful for database relationships and performance.

Add a separate immutable, unique, randomly generated public_id using UUIDv4 (or an equivalently strong non-enumerable identifier).

All browser routes and client-facing API endpoints must use public_id, not the sequential internal database ID.

For example:

/portal/projects/{public_id}

rather than:

/portal/projects/1

Apply this architecture consistently

Review the application's client-facing resources and use non-enumerable public IDs for resources that could otherwise expose sequential database identifiers, including as appropriate:

projects
patents
claims
analysis runs
findings
evidence/records
uploaded files
reports
other client-confidential resources

Internal numeric IDs may remain inside the database and server-side relationships.

Do not unnecessarily expose them through URLs, API responses, HTML, or frontend state.

Important security requirement

This is defense in depth only.

Possession or knowledge of a valid public_id must NEVER constitute authorization.

Every request must continue to authenticate the user and independently verify server-side that the user is authorized for the client/resource associated with that public_id.

A valid UUID belonging to another client must return access denied/not found as appropriate.

Do not weaken any existing client isolation or authorization checks.

Existing records

Safely backfill public_id values for existing records where required.

Add appropriate UNIQUE and NOT NULL constraints/indexes after backfill as appropriate.

/portal/projects/{public_id}
