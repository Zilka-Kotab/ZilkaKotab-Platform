CRITICAL — CLIENT CONFIDENTIALITY AND TENANT ISOLATION

Treat all client portal information as confidential law-firm client information. The system must use deny-by-default tenant isolation.

Every client-owned resource—including projects, tool data, uploaded files, generated outputs, conversations/results, and future AI-tool data—must be associated server-side with a specific client_id or equivalent tenant identifier.

Never trust a client ID, project ID, tool ID, user ID, role, or permission supplied by the browser. For every protected request, derive the authenticated user from the validated server-side session and independently determine that user's permitted client scope from the database.

Every database query involving client information must enforce that permitted client scope server-side. Do not retrieve an object first and merely hide it in the frontend if the user lacks permission.

Use deny-by-default authorization: if authorization cannot be positively established, return access denied.

Prevent IDOR/BOLA vulnerabilities. Knowing or guessing another client's UUID, project ID, URL, API endpoint, filename, or other identifier must never provide access.

Uploaded files and generated documents must follow the same tenant-isolation rules as database records. Do not place confidential client files in publicly accessible static directories or expose permanent public URLs. File downloads must pass through authenticated, authorized access controls or use short-lived appropriately scoped signed URLs.

Search, filtering, autocomplete, counts, dashboards, logs, error messages, exports, AI-tool history, and metadata must not reveal the existence or contents of another client's information.

ADMIN access is the only role permitted to access all clients. ATTORNEY access must be limited to specifically assigned clients. CLIENT access must be limited to specifically assigned client organization(s) and resources.

Database/API authorization must remain authoritative even if frontend code is bypassed entirely.

Do not expose confidential information in application logs. Never log Microsoft tokens, session IDs, credentials, secrets, or unnecessary client document contents.

Use parameterized database queries/ORM protections, secure input validation, appropriate rate limiting, secure headers, CSRF protections, and production-only secure cookies.

For any future AI tool, do not send one client's information to another client's context, retrieval index, vector store, conversation, cache, or project. AI/RAG/vector-search data must be tenant-scoped just like conventional database data.

Before production use with real client information, perform explicit cross-tenant security tests using at least two test clients (Client A and Client B), two client users, an attorney assigned only to Client A, and an ADMIN.

Attempt cross-client access by manipulating URLs, query parameters, API bodies, project IDs, client IDs, file IDs, tool IDs, direct API calls, search requests, exports, and file-download URLs. Document the test results.

Do not populate the development/test environment with real confidential client information. Use synthetic test data until these isolation tests pass.
