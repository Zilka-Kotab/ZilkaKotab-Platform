The complete USPTO claim-text issue is fixed. Before moving forward, make one small UI correction to the existing claims display, and then implement the next Patent Infringement Monitor component: Claim Limitation Analysis.

Do NOT connect Microsoft Copilot or another AI provider yet. Build the data model, UI, editing/review workflow, and future AI contract.

0. Clean up the existing claim display

There is currently unnecessary duplication in the dependent-claim display.

For example, the UI currently displays:

Claim 3 — depends on claim 1

followed immediately by the authoritative claim text:

3. The apparatus of claim 1, wherein...

The phrase “depends on claim 1” in the header is redundant because the dependency is already stated in the authoritative claim text directly underneath it.

Please remove the dependency notation from the visible claim header.

The display should simply be:

Claim 3

3. The apparatus of claim 1, wherein...

Apply this consistently to all dependent claims.

Important: Do NOT remove the underlying dependency data from the database. Continue storing and using the structured dependency relationship (depends_on_claim, etc.) for analysis and future functionality. This is only a UI/display change.

Independent claims should likewise simply display:

Claim 1

followed by the complete authoritative claim text, plus any appropriate status badge such as Selected for monitoring.

Avoid duplicating information in claim headers that is already evident from the authoritative claim language.

1. Claim Analysis workspace

For every independent claim selected for monitoring, add:

Analyze Claim

This should open a dedicated Claim Analysis workspace.

At the top show:

Patent Number
Claim Number
Monitoring Status

followed by:

Authoritative Claim Text

Display the complete current USPTO claim text read-only.

This authoritative text must never be modified by limitation editing.

2. Claim limitations

Below the authoritative claim, create:

Claim Limitations

Each limitation should be a separate structured record containing:

public UUID;
claim/version association;
sequence/order;
identifier such as 1A, 1B, 1C;
limitation text;
creation method: MANUAL or future AI_GENERATED;
verification status;
verified by;
verification timestamp;
created/updated timestamps.

ADMIN and ATTORNEY should be able to:

Add limitation
Edit limitation
Split limitation
Merge adjacent limitations
Reorder limitations
Delete an erroneous limitation
Verify the limitation structure

CLIENT users may view verified limitations but should not modify attorney-reviewed claim analysis unless explicitly permitted later.

3. Do not oversimplify claim parsing

Do not assume that every semicolon, colon, paragraph, or line break automatically represents a separate legal limitation.

The future AI provider will propose a useful limitation structure based upon the complete authoritative claim.

For this phase, manual creation/editing is the operational fallback.

Do not automatically create limitations using simplistic punctuation splitting merely to populate the interface.

4. Verification

Provide two limitation-structure states:

DRAFT

VERIFIED

An authorized attorney/admin should be able to select:

Verify Limitation Structure

Record who verified it and when.

If a VERIFIED limitation structure is subsequently modified, automatically return it to DRAFT and preserve the previous verification/history.

5. Claim-version relationship

Limitations must attach to a specific claim version, not merely the claim number.

This is important because Refresh from USPTO can create a new authoritative claim version.

If a new authoritative claim version is created:

preserve the previous limitation structure;
do not delete its history;
do not silently represent the previous limitation structure as verified against the new claim version; and
clearly indicate that the new claim version requires review/analysis.
6. Prepare automatic AI limitation generation

Extend the existing AI-processing architecture with an operation such as:

PARSE_CLAIM_LIMITATIONS

AI-generated limitations must initially be:

and:
