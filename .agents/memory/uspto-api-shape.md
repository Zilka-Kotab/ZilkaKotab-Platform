---
name: USPTO Open Data Portal API shape
description: Non-obvious request and document URL details for USPTO Patent File Wrapper imports.
---

The Patent File Wrapper search endpoint accepts a patent number through the GET `q` query parameter; the field-qualified POST form can return 400. For public analytics, live records expose `firstApplicantName`, `applicantBag`, `examinerNameText`, `groupArtUnitNumber`, and prosecution events even when summary documentation omits examiner fields. `firstApplicantName` queries work for applicant searches, while nested `assigneeBag.assigneeNameText` queries may return no matches. Broad text queries produce false positives but their `firstApplicantName` facet can discover legal-name aliases (including acronym expansions such as IBM). Search facets and filtered `count` queries provide complete aggregate totals without downloading every matching record. Associated grant metadata exposes the XML download under `fileLocationURI`, and that URL may redirect before returning the grant XML. Grant XML may nest multiple `claim-text` elements inside one claim, so claim parsing must collect every descendant text node in order. The current ODP assignments endpoint is keyed by a known application number (`/api/v1/patent/applications/{applicationNumberText}/assignment`); it is not an assignee-name search endpoint.

**Why:** The public USPTO documentation describes both GET and POST search access, but the live endpoint behavior, searchable fields, and associated-document field names are stricter than the generic examples. The first `claim-text` element is only the opening paragraph for many claims. Assignment retrieval also requires candidates seeded by a search that supplies application numbers; it cannot discover unrelated patents globally by party name.

**How to apply:** Keep identifiers and applicant names normalized locally. If applicant facets produce multiple plausible legal entities, ask users which names belong in scope instead of silently combining them. Use facets/counts for totals and trends rather than counting a capped page sample. Filter issued records by `patentNumber` and `grantDate` for recent-grant counts; explicit inactive status facets do not establish that the remaining grants are in force. Pace and retry requests because parallel aggregate queries can trigger ODP 429 responses. Follow redirects for `fileLocationURI`, recursively collect all claim descendant text, and treat missing grant XML, claims, or outcome coverage as incomplete rather than inventing metadata. For assignments, use the known-application endpoint and clearly disclose any candidate-coverage limit.
